# 模糊搜索手动测试用例

覆盖 2026-11 四项搜索优化：本地收藏扩字段（改进3）、TMDB person `known_for` 收割（改进1）、
学习别名（改进4）、AI 查询改写前置（改进2）。每条用例给出步骤、明确预期、以及从**诊断面板**读取的判定标志。

## 0. 环境准备

| 项 | 要求 |
|---|---|
| 运行方式 | `npm run tauri dev`（dev 模式才有 DevTools，右键 → 检查 / F12） |
| AI 提供商 | DeepSeek，模型 `deepseek-flash`，baseUrl `https://api.deepseek.com` |
| TMDB | **必须配置 key** 并开启（改进 1/2 的验证全依赖它） |
| 搜索引擎 | 默认 DuckDuckGo 即可；若网络不可达 DDG 建议配 Serper（见 §5 排障） |
| 诊断 | AI 设置 → 搜索诊断开启（默认开）；每次搜索后读 `lastSearchDiagnostics` |
| 推理力度 | AI 搜索推理力度默认 `off` 即可；调高会显著增加 AI 全链路耗时 |

**每条用例开始前清缓存**（DevTools Console 执行）：

```js
// 清三类缓存：搜索结果(2h) / 查询改写 / 学习别名
['media_tracker_search_v2_', 'media_tracker_query_rewrites_v1', 'media_tracker_learned_aliases_v1']
  .forEach(p => Object.keys(localStorage).filter(k => k.startsWith(p)).forEach(k => localStorage.removeItem(k)));
```

> 只清搜索缓存（保留改写和别名）的做法在具体用例中单独注明。

**诊断面板字段对照**（搜索诊断卡片 → steps）：

| step 名 | 含义 |
|---|---|
| `缓存检查` | 2h 结果缓存 |
| `并行阶段` | TMDB / Bangumi / 插件并行搜索（取最慢） |
| `查询改写` | **本轮新增**。details JSON：`terms`（改写候选）、`validated`（TMDB 验证通过的候选）、`aiNeeded`（false = 跳过了主 AI 调用） |
| `网页搜索上下文` | 引擎搜索（有此步骤 = 没跳过 AI 路径） |
| `AI 生成候选作品` | 主 AI 调用（出现 = 未走快路径） |

## A. 基线回归（先跑，确保没被优化破坏）

### TC-A1 精确英文标题
- **步骤**：清缓存 → 搜索 `Inception`
- **预期**：
  1. 首位结果 = Inception (2010)，Movie，海报/年份/评分正常
  2. **诊断无「查询改写」步骤**（基础结果有精确命中，改写不触发）
  3. **诊断无「AI 生成候选作品」步骤**（精确命中跳过 AI）
  4. 总耗时 **< 3s**（TMDB 命中 + 富化）
- **记录**：totalDurationMs

### TC-A2 缓存命中
- **步骤**：TC-A1 后**不清缓存**，原样再搜一次 `Inception`
- **预期**：诊断只有 `缓存检查 0ms`，总耗时 **< 50ms**，结果与上次相同

### TC-A3 精确中文标题
- **步骤**：清缓存 → 搜索 `盗梦空间`
- **预期**：首位 = 《盗梦空间》(2010)，全部字段简体中文（query 语言跟随规则）；无改写、无 AI 步骤

### TC-A4 类型过滤联动
- **步骤**：选中「电视剧」筛选 → 搜索 `神盾局特工`
- **预期**：结果全部为 TV_SERIES 类型；首位命中《神盾局特工》/ Agents of S.H.I.E.L.D.（2013）

## B. AI 查询改写（改进 2，核心收益）

### TC-B1 缩写快路径：`AOS`
- **步骤**：清全部缓存 → 搜索 `AOS`
- **预期**：
  1. **诊断「查询改写」details**：`terms` = 1 个候选（应为 `Marvel's Agents of S.H.I.E.L.D.` 或 `Agents of S.H.I.E.L.D.` 类），`validated` 长度 ≥ 1，**`aiNeeded: false`**
  2. **诊断无「网页搜索上下文」「AI 生成候选作品」**（快路径生效的铁证）
  3. 首位结果 = Agents of S.H.I.E.L.D.（2013，TV_SERIES），**海报/年份来自 TMDB**（非 AI 生成）
  4. 总耗时 **2–6s**；不出现「搜索较慢」提示（10s 阈值）
- **判定**：若 `terms` 有 2–3 个候选 → 快路径不生效（设计如此，防误杀），走 AI 全链路 10–30s，结果仍应正确。**记录实际 terms**，这反映模型置信度。

### TC-B2 改写缓存生效
- **步骤**：TC-B1 后，清**搜索缓存**（保留改写缓存）→ 再搜 `AOS`
- **预期**：「查询改写」步骤 **< 100ms** 且 `terms` 与上次完全一致；仍无 AI 步骤；总耗时 1–2.5s

### TC-B3 主角名快路径：`emily dickinson`
- **步骤**：清全部缓存 → 搜索 `emily dickinson`
- **预期**：
  1. 改写 `terms` = 1 个候选（`Dickinson`），`validated` ≥ 1，`aiNeeded: false`
  2. 首位结果 = **Dickinson (2019)，TV_SERIES**（Apple TV+ 剧集，Hailee Steinfeld 主演）
  3. 若 TMDB person 结果的 `known_for` 里还有标题含 "dickinson" 的纪录片 → 可能作为附加结果出现（≤5 条），**不是缺陷**
  4. 总耗时 2–6s
- **判定**：若走了 AI 全链路（诊断有 AI 步骤），检查结果是否仍首位 Dickinson——改写候选会以 `[CANDIDATES]` 注入 AI prompt，准确度应保持；记录耗时对比。

### TC-B4 长描述句
- **步骤**：清全部缓存 → 搜索 `10年前的，跟外星人相关的电视剧，里面有个局长，还有个华裔演员好像叫daisy`
- **预期**：
  1. 结果**首位 = 神盾局特工 / Agents of S.H.I.E.L.D.**（2013，TV），描述含异人族/外星剧情，cast 含 Chloe Bennet（Daisy Johnson 扮演者）、Clark Gregg（寇森局长）
  2. 改写行为二选一（都算通过，记录实际）：
     - 单候选 + 验证 → 快路径，总耗时 **2–6s**
     - 多候选 → AI 全链路 10–30s，但 `[候选]` 注入后 AI 仍应锁定神盾局特工
  3. **「10年前」解析正确**：今天是 2026 年，"10 年前" ≈ 2016 年前后开播的剧——若 AI/改写把年份理解错（如返回 1990 年代剧），记录为日期锚缺陷
- **注意**：此查询 DDG/引擎上下文可能贡献噪声结果，相关性门控会清掉 0 分噪声；若首位被噪声占据 → 缺陷，记录截图。

### TC-B5 负面：无意义查询
- **步骤**：清全部缓存 → 搜索 `asdfqwerty zz`
- **预期**：改写返回 `terms: []`（或无效候选）→ 不跳过 AI → AI 全链路 → **最终无结果或零星噪声**；不崩溃、无红色错误横幅（提示"未找到结果"属正常）

### TC-B6 负面：无 AI key 降级
- **步骤**：移除 DeepSeek key（AI 设置清空）→ 清缓存 → 搜索 `AOS`
- **预期**：**改写步骤整体不出现**（无 key 门控，不白等 4s）；TMDB/引擎无命中 → 无结果 + "未找到"提示；总耗时应 < 10s（不出现 4s 改写空等）
- **恢复**：重新填回 key

## C. TMDB person `known_for` 收割（改进 1）

### TC-C1 人物名 → 代表作
- **步骤**：清全部缓存 → 搜索 `keanu reeves`
- **预期**：
  1. 结果中出现 TMDB 来源的代表作（如 John Wick / The Matrix 系列），**≤ 5 条**，均带真实海报与年份
  2. 点开其中一条 → 详情完整（导演/主演/简介由 TMDB 富化自动补全）
  3. 走 AI 全链路（收割**有意不**跳过 AI——保守设计），总耗时 10–30s 属正常；诊断「AI 生成候选作品」存在
  4. **无全量 Filmography 刷屏**（收割只保留标题与查询有重叠的条目；"keanu reeves" 与片名无重叠时可能 0 条收割——此时结果纯 AI，也算通过，记录即可）
- **判定核心**：结果不崩、不刷屏、带 TMDB 元数据。

### TC-C2 回归：精确标题不受收割污染
- **步骤**：清全部缓存 → 搜索 `The Matrix`
- **预期**：首位 = The Matrix (1999)；无 known_for 噪声条目（基础命中 > 0 → 收割门控关闭）；无改写、无 AI 步骤

## D. 学习别名（改进 4）

### TC-D1 记录映射
- **步骤**：TC-B1 的结果中，把《神盾局特工》**加入收藏**（任一分类）
- **预期**：DevTools 查看 `localStorage.media_tracker_learned_aliases_v1` → 出现 `"aos": { "title": "<所收藏条目的标题>", "ts": ... }`

### TC-D2 别名快路径（终极提速）
- **步骤**：清**搜索缓存和改写缓存**（**保留**别名缓存）→ 再搜 `AOS`
- **预期**：
  1. **诊断无「查询改写」步骤**（别名命中 → 计为精确命中 → 不触发改写）
  2. **无 AI 步骤**；总耗时 **1–2s**
  3. 首位 = 神盾局特工（上次收藏确认的标题优先去重）
- **判定**：这是四项优化完成后的终极状态：`AOS` 从 6–16s（改造前）→ 1–2s。

### TC-D3 相等映射不记录
- **步骤**：清别名缓存 → 搜索 `dickinson` → 把 Dickinson (2019) 加入收藏 → 查看别名存储
- **预期**：**无** `"dickinson"` 键（归一化后与标题相等，学习无意义，跳过）

### TC-D4 热门推荐不污染

## 5. 排障对照

| 症状 | 原因 | 处理 |
|---|---|---|
| 诊断「网页搜索上下文」≈ 10s 且 AI 步骤 > 40s、DDG 配额打满 | DDG 在当前网络不可达，AI 工具循环反复空转 | 配 Serper key 或换网络；此现象值得后续加熔断（已知问题） |
| 改写 `terms` 恒为 `[]` | 模型无候选 / 候选与原查询等值被过滤 / key 失效 | 看 AI I/O 日志确认模型原始返回；换 deepseek-v4-pro 对比 |
| 「查询改写」步骤存在但耗时 ~4s 且 terms 空 | 改写调用撞 4s 超时（推理模型常见） | 把模型换 deepseek-flash 或调低搜索推理力度 |
| 结果语言与查询不一致 | 改写词语言与原查询不同导致 TMDB 返回语言差异 | 记录现象（别名快路径下收藏确认的标题语言优先，属设计取舍） |
